# Personal Work Agent

面向个人工作的 AI 技能包，当前版本 **0.9.8**。

Personal Work Agent（PWA）把一个工作请求推进为有依据、可检查的结果：先理解目标与现有材料，再选择合适的工作流和可用工具，在授权范围内执行，最后核对实际结果并说明仍未验证的部分。适用任务包括维护已有代码、从零构建软件、制作办公交付物，以及开展投资研究。

这个仓库包含两个技能、配套参考说明、输出模板，以及校验和评估材料。技能提供工作方法与执行约束；具体能读取什么、运行什么、生成什么，取决于当前 AI 宿主提供的工具、执行环境、已安装技能和用户授权。

## 适合处理哪些任务

| 工作方向 | 典型任务 | 重点关注 |
| --- | --- | --- |
| 现有代码维护 | 排查和修复 Bug、实现功能、重构、审查分支或 PR、分析 CI 失败、评估架构问题 | 读取项目规则，保留现有改动，依据源码和配置选择检查方式，验证受影响的行为 |
| 新软件项目 | 从需求构建应用、服务、CLI、库或原型，继续尚未完成的首次构建 | 明确首版范围，选择适当架构，完成可运行的核心流程，并验证实际使用结果 |
| 办公交付物 | 整理研究材料、制作 Word、PDF、表格、演示文稿、会议输出或邮件草稿 | 明确读者和用途，复用格式专用技能，核对来源、数字、版式和可编辑性 |
| 投资研究 | 公司与行业分析、财务质量分析、估值、投资论点与情景比较 | 优先使用原始披露，注明数据期间和单位，区分事实与推断，讨论风险与反方观点 |

PWA 更适合需要项目背景、多步骤执行或跨能力协作的工作。对于一个独立的小操作，例如调整某个表格公式，也可以直接使用对应的专业技能。

## 两个技能如何分工

### Personal Work Agent：任务入口与整体协调

[`personal-work-agent`](skills/personal-work-agent/SKILL.md) 负责识别任务类型、建立必要上下文、选择工作流、检查权限，并在交付前核对结果。它根据当前任务读取相关参考文件，避免每次都加载所有说明。

它会优先复用项目已有工具和当前可用的专业技能。例如，文档排版交给文档技能，浏览器复现使用可用的浏览器工具，框架相关修改遵循项目实际采用的技术栈。某项能力未安装或不可调用时，需要说明限制并寻找适当替代方式。

### Project Builder：从需求到可验证的首版

[`project-builder`](skills/project-builder/SKILL.md) 专注于新软件项目，也负责继续尚未完成的初次构建。它可以直接使用，也可以由 PWA 在处理新项目时选用。

构建时会沿用已经确认的需求、约束和验收标准，从一个有用的核心用户流程开始，逐步完成界面、接口、数据或 CLI 行为等实际需要的部分。目标是交付可运行且经过相应验证的首版，并给出启动方式、环境要求与剩余问题。

首版完成后，后续修复和增强通常回到 PWA 的代码维护工作流。技能之间的路由会复用当前对话信息；选用 Project Builder 本身不会新建聊天或启动其他代理。

## 一次任务通常怎样推进

1. **确认目标和边界。** 识别用户要的是解释、诊断、方案、实现、审查还是交付文件，复用对话中已经确认的决定。只有会实质改变结果的缺失信息才需要澄清。
2. **读取相关上下文。** 检查项目规则、源码、配置、现有文档或用户提供的材料，保留无关文件和已有改动。对长任务或续接任务，核对当前状态与交接信息。
3. **选择主要工作流。** 按交付目标选择代码维护、新项目构建、办公交付或投资研究，再补充当前环节所需的专业能力。
4. **在授权范围内执行。** 控制修改范围，检查命令的实际作用，避免顺手安装工具、改全局配置或操作外部系统。已经明确授权的同一动作无需反复确认。
5. **验证实际结果。** 根据任务选择相关测试、构建、接口或浏览器检查、文件检查、页面渲染与实际图像检查，或来源与计算核对。验证方式应覆盖用户要求的结果。
6. **交付并说明限制。** 汇报完成了什么、依据是什么、哪些部分仍未验证，以及是否存在需要用户处理的阻碍。

步骤的深度随任务变化。一个明确的小修改可以直接检查、修改和验证；较复杂的产品或架构选择才需要更完整的讨论和计划。

## 工作方式与设计重点

### 以当前项目和实际工具为准

用户要求、仓库规则和当前证据决定执行方式。个人技术偏好只用于补足未指定的选择；技能也会检查工具是否实际可用。仓库中的可选能力名称用于指导选择，并不表示这些工具都已随本包安装。

涉及较多跨文件调用关系时，可以使用已可用的 CodeGraph 能力辅助导航，并结合当前源码核对。没有对应能力时，继续使用原生搜索和文件阅读；安装、索引或配置 MCP 需要单独处于授权范围内。

### 保留上下文与现有工作

接续任务时会复用已确认的范围、重要决定、已有成果和验收要求，再核对当前文件与旧记录的差异。任务需要长期保存的信息应优先写入项目现有文档；日常小修改无需固定生成一组计划和状态文件。

用户请求复盘时，可以根据实际记录分析问题、影响和改进建议。提出建议与应用改进分别处理，复盘本身不会自动修改技能、全局规则或项目配置。

### 对外部动作检查具体授权

本地修改和检查按任务范围执行。安装依赖、提交或推送代码、修改共享文档、发送消息、创建外部资源等动作，需要有对应的授权，并遵守宿主的审批规则。生产部署、删除、购买和访问权限变更等操作需要明确的动作指令。

这些规则属于任务执行指导，宿主自身的权限控制仍然有效。投资研究仅提供分析支持，不执行证券交易、资金转移或投资账户变更。

### 让完成结论有可核对的证据

不同结果需要不同证据。例如，服务启动成功只说明进程已启动；异步任务需要观察最终状态；办公文件的生成、渲染、实际图像检查和原生应用打开是不同的检查环节。

包内提供 [Python 命令证据工具](skills/personal-work-agent/references/command-evidence.md)，用于记录获授权命令的参数、工作目录、进程状态和输出，并从记录生成核验信息。它适用于多命令验证、重试或精确运行时版本报告；使用前需要可用且获授权的 Python 环境。缺少记录或必要观察时，应保留“未验证”状态。

该工具采用显式调用方式，不会自动拦截宿主的所有回答，也不构成沙箱、后台任务管理器或权限授予机制。

## 使用示例

下面的示例假定相应技能已安装，并且当前环境能够访问任务所需的文件与工具。实际调用名称以宿主技能目录为准，部分宿主支持自然语言指名。

### 维护已有项目

```text
用 $personal-work-agent 修复这个项目中搜索结果翻页后丢失筛选条件的问题。
先查看项目规则和已有实现，保留其他未提交改动，完成修复并验证相关用户流程。
```

### 只诊断或评估

```text
用 $personal-work-agent 分析这个导入模块最值得改善的架构问题。
根据当前源码给出问题、影响和建议，只做评估，不修改代码。
```

### 从零构建软件

```text
用 $project-builder 在指定目录构建一个个人阅读清单工具。
首版支持添加、搜索和标记已读，数据需要在重启后保留。
完成可本地运行的版本，提供启动方式并验证这些核心流程。
```

### 接续尚未完成的任务

```text
用 $personal-work-agent 根据已确认的任务简报继续开发。
先核对当前代码、交接记录和已完成的验证，再推进剩余范围。
```

### 制作办公交付物

```text
用 $personal-work-agent 根据这些资料制作一份面向项目负责人的进展汇报。
突出已完成内容、关键数据、风险和待决策事项，保留可编辑文件并检查版式。
```

### 开展投资研究

```text
用 $personal-work-agent 根据这家公司最新的正式披露，分析业务、财务质量和估值。
注明数据期间、单位和来源，列出关键假设、反方观点与需要持续观察的指标。
```

提出任务时，提供目标目录或材料、预期结果、主要约束和验收例子，通常有助于更快进入执行。

## 个性化设置

非敏感偏好保存在 [`user-profile.md`](skills/personal-work-agent/references/user-profile.md)。当前默认以中文沟通，工程偏好包括 TypeScript、Next.js、React 和 Node.js，也包含 Java、Python、Notebook 等次要环境。

可以按需要补充界面风格、可访问性目标、提交信息习惯、托管服务、文档风格或研究框架。已有项目的技术栈和用户的明确选择优先；数据库、缓存、消息队列等组件只在需求支持时引入。请勿在技能、模板或记录中保存密码、令牌、Cookie、私钥或恢复码。

## 宿主与安装说明

本仓库包含 Codex 插件元数据，并提供其他宿主的适配指导。安装时需要根据目标宿主处理技能目录、引用资源和发现机制。

| 使用环境 | 本仓库提供的材料 | 需要核对的事项 |
| --- | --- | --- |
| Codex | `.codex-plugin/plugin.json`、两个技能目录与图标资源 | 当前插件或技能安装机制、目录中的实际名称，以及安装后是否能发现和调用 |
| Claude Desktop | 单技能打包与导入指导 | 按目标界面导入；聊天环境、Cowork 与 Code 的文件和工具访问范围可能不同 |
| DeepSeek Harness | 技能目录与提供者配置的适配指导 | 实际版本、配置的技能根目录、同名优先级与可用工具 |

完整说明见 [USAGE.md](USAGE.md) 和 [宿主兼容性参考](skills/personal-work-agent/references/host-compatibility.md)。打包完整、安装成功、目录可见和实际任务通过需要分别验证；一个宿主上的结果不能证明另一个宿主也通过。

## 校验与能力边界

在仓库目录中，可使用已有 Python 环境执行基础结构校验：

```bash
python3 -B evals/check.py
python3 -B evals/check.py --manifest-only
```

这些检查分别覆盖评估配置与版本一致性，以及插件元数据、本地路径和 SVG 图标。单元测试、技能打包校验和行为评估的运行方式见 [USAGE.md](USAGE.md)、[评估协议](evals/protocol.md) 与 [行为评估说明](evals/behavior.md)。

结构校验或单元测试通过，不代表模型完成了全部任务场景，也不代表获得生产就绪、安全认证或跨宿主兼容性保证。仓库中的历史评估记录应按各自版本和覆盖范围阅读。令牌节省、质量提升、故障恢复或缓存行为等结论，也需要对应工作负载与运行记录支持。

PWA 本身不提供模型服务、工具凭据、定时调度器或常驻后台执行器。最终交付能力来自当前宿主、可用专业技能与用户授权的组合；无法完成的检查应在交付时明确说明。
