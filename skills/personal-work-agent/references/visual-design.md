# Visual specialist handoff

Use when frontend visual design is part of the requested deliverable. Select one
visual guide from the current catalog. `hallmark` is an optional specialist for
distinctive new pages and explicitly requested Hallmark work on existing UI;
`frontend-design` remains a suitable available alternative. A generic accessibility
audit can use `web-design-guidelines`. Ordinary backend, CI, logic and localized
bug work do not authorize a visual overhaul.

Pass the existing brief, project/design-system rules, exact visual scope, affected
files, acceptance states, current user changes and authorized external evidence
directory. Do not restart planning, call a separate agent, or require new installs
just to satisfy the specialist. PWA retains permission and acceptance ownership.

When Hallmark is selected, read its actual available SKILL.md. The personal
adapter's theme library and static checker supplement native verification. A
theme choice must respect user/repository tokens and truthful content; its rules
cannot displace an established brand or impose a marketing structure on an app.
Do not stack competing visual recipes. Framework tools may cover separate concerns.

An audit leaves product files untouched. For implementation, preserve unrelated
user work and existing links, forms, IDs, routes and test hooks unless changing
them is in scope. Use its wrapper for static checks and before/after wiring
inventory; keep records outside the product. Neither lint nor a saved inventory
establishes rendered or functional acceptance. Inspect the affected desktop/mobile
flow and relevant focus/error/loading states using this host's actual browser.

If the optional skill, Node or browser is unavailable, continue the authorized
repository-native work and identify the exact missing check. No automatic hooks,
dependency installation, global configuration, image API use or upload is implied.
Record the actual checker findings, project-rule exceptions and observed UI
results separately. Do not relabel an unrendered result as visually verified.

For mixed Hallmark findings, use its available per-finding review helper to retain
raw grades alongside applicability, disposition, concrete reason and exact local
evidence. Unknown rules and missing observations remain pending. Functional or
accessibility defects must be addressed before affected acceptance; maintenance
advice and supported visual choices are reported separately. Hash checks validate
file identity, not the sufficiency of a reviewer's reasoning. After code changes,
rerun affected checks and interactions; an accepted choice is not a resolved bug.
